# 草野球打席・スコア記録Webアプリ 仕様書

## 1. 概要
草野球チーム向けに、打席結果とスコアをスマホから記録し、複数端末でリアルタイムに共有・閲覧できるWebアプリ。
チームIDをURLパラメータに含めることで、パスワード不要・共有リンクだけでチームの画面にアクセスできる。

## 2. 想定ユーザー・利用シーン
- 主な用途:自分の草野球チームでの打席結果・スコア記録
- 利用場面:試合中にスマホで球場から入力(複数人が同時に入力する可能性あり)
- 加えてPCからの管理画面(チーム管理・アプリ全体管理)も必要

## 3. 認証方式
- **チームメンバー向け**:チームIDをURLパラメータに含めた共有URLでアクセス。パスワード不要。
  - 例:`https://appname.vercel.app/team/ab3x9k2m`
  - URLを開くだけでそのチームの画面(選手一覧・試合一覧など)に直接遷移し、そのまま入力可能
  - チームID自体は推測されにくいランダム文字列(8桁以上推奨)
- **チーム管理者向け**:チーム内の管理操作(選手管理・試合管理など)は基本メンバーと同じURL方式で実施
- **アプリ全体の管理者向け**:別途管理者ログイン(ID/パスワード等の認証)が必要な管理画面を用意

## 4. 機能一覧

### 4.1 選手管理
- 選手の登録・編集・削除(名前・背番号)

### 4.2 試合管理
- 試合作成(日付・対戦相手・球場)
- 打順・スタメン設定

### 4.3 スコアボード
- イニングごとの自チーム/相手チームの得点入力
- 野球盤形式の得点表(1〜9回、合計)を自動表示
- 複数端末からのリアルタイム反映

### 4.4 打席記録
- 打席結果の入力(詳細版、下記参照)
- 選手を選んで結果をタップで記録、打順は自動で進む
- 試合ごとの打席ログ一覧
- 複数人が同時入力する可能性があるため、入力後は即座に他端末へ反映し「直前の記録」を全員が確認できる状態にする

**打席結果の種類(詳細版)**
単打・二塁打・三塁打・本塁打・四球・死球・犠打・犠飛・失策出塁・凡打・三振

### 4.5 成績集計(自動計算)
- 打率(安打÷打数)
- 出塁率(出塁数÷打席数)
- 長打率(塁打数÷打数)
- OPS(出塁率+長打率)
- 打数・安打数・本塁打数などの基本カウント
- シーズン通算成績、試合ごとの成績の両方を表示

### 4.6 チーム管理画面(PC向け・チーム管理者用)
- 選手の一括管理(登録・編集・削除)
- 試合結果の一覧・編集・削除
- 成績データの確認・修正
- チームID(共有URL)の確認・再発行
- チーム基本情報(チーム名など)の編集

### 4.7 アプリ管理画面(PC向け・要管理者ログイン)
- 管理者専用のログイン機能(ID/パスワード認証)
- 全チームの一覧・状況確認
- チームの作成・削除(運営側での対応用)
- 利用状況の把握(アクティブチーム数、試合数など)
- 不正利用・不要データの管理

## 5. データ構造(案)

| エンティティ | 主な項目 |
|---|---|
| チーム | チームID、チーム名、作成日 |
| 選手 | チームID(紐付け)、名前、背番号 |
| 試合 | チームID、日付、対戦相手、球場、スコア(イニングごと) |
| 打席記録 | 試合ID、選手ID、打順、結果、イニング |
| 管理者 | 管理者ID、認証情報(アプリ管理画面用) |

## 6. 画面構成

### スマホ画面(メンバー向け・URL直接遷移)
1. チームホーム(選手一覧・試合一覧)
2. 選手管理画面
3. 試合作成・スタメン設定画面
4. 打席入力画面(結果ボタンでタップ入力)
5. スコアボード表示画面
6. 個人成績一覧画面(通算・試合ごと)

### PC画面(チーム管理者向け)
- チーム管理ダッシュボード(選手・試合・成績の一括管理、チームID確認)

### PC画面(アプリ管理者向け・要ログイン)
- 管理者ログイン画面
- 全チーム一覧・管理ダッシュボード

## 7. ルーティング構成(案・Next.js想定)
- `/team/[teamId]` … チームホーム(選手・試合一覧)
- `/team/[teamId]/game/[gameId]` … 個別試合の打席入力・スコアボード
- `/team/[teamId]/stats` … 通算成績画面
- `/team/[teamId]/admin` … チーム管理画面(PC向け)
- `/admin/login` … アプリ管理者ログイン
- `/admin/dashboard` … アプリ全体管理画面(要認証)

## 8. 技術構成(推奨)
- フロントエンド:React + TypeScript(スマホ最適化UI、PC管理画面はレスポンシブ対応)
- バックエンド/DB:Firebase(Firestoreでリアルタイム同期 + Hosting)
- チームメンバー認証:チームID方式(URLパラメータ、パスワード不要)
- アプリ管理者認証:Firebase AuthなどによるID/パスワード認証

## 9. 同時編集への対応方針
- 打席記録は「1打席=1レコード」のため基本的に競合が起きにくい
- 「現在の打者・アウトカウント」など試合状態はリアルタイム同期が必要 → Firestoreのようなリアルタイム同期DBを採用
- 入力後は即座に他端末に反映し、二重入力を防止

## 10. 今後決めること(実装時に検討)

## 11. 実装前確定事項

§1〜§10で曖昧だった点を、実装着手前に以下のとおり確定する。すべて「最小構成」を基本方針とする。

### 11.1 確定した方針

| 項目 | 決定 |
|---|---|
| 試合進行 | 打席結果をタップすると打順が+1されるのみ。イニングの表裏切り替えは手動ボタン。アウトカウント・走者状況・現打者の状態は保持しない |
| スコアボード | 1〜9回+合計の得点表。自チーム・相手チームともにセルをタップして得点を手入力する。打席記録とは連動させない(不整合は許容) |
| 相手打線 | 相手チームの打席は記録しない。相手の情報はスコアボードの得点手入力のみ |
| 成績指標 | 打率・出塁率・長打率・OPS + 基本カウント + 打点。通算成績と試合ごと成績の両方を表示 |
| 技術スタック | Next.js 15 (App Router) + TypeScript / ホスティングは Vercel / DB・リアルタイム同期は Firestore / アプリ管理者認証のみ Firebase Auth |
| 選手削除 | 物理削除せず論理削除(`archived: true`)。過去試合の打席記録は保持し、成績にも反映する。選手一覧では非表示 |
| シーズン | 西暦年度で区切る。試合に `season`(数値・西暦)を持たせ、通算成績は同一シーズン内で集計 |
| チームID | 12文字の暗号学的乱数(base32: 英小文字a-z + 数字2-7)。チーム管理画面から再発行可能で、再発行すると旧URLは即無効(同一 teamId ドキュメントのIDを付け替えるのではなく、新IDで作り直し既存サブコレクションを移行) |
| 誤入力対応 | 打席記録には「直前のレコード」を含む各レコードの編集・削除UIを必ず用意する |
| 打点入力 | 打席入力時に 0〜4 のステッパーで手動入力する。走者進塁からの自動計算は行わない |
| Firestore セキュリティルール | teamId を知る全員が、その teamId 配下のドキュメントのみ読み書き可能。アプリ管理系の操作は `admins/{uid}` ドキュメントの存在で判定。Firebase App Check を有効化する |
| アプリ管理者の発行 | Firebase Auth でユーザーを作成し、`admins/{uid}` ドキュメントを手動作成することで管理者とする。初期管理者は seed スクリプトで作成 |
| オフライン対応 | Firestore のオフライン永続化(IndexedDB)を有効化する。オフライン中の入力は復帰時に自動同期。競合解消は最終書き込み優先(打席は1打席=1レコードのため競合はまれ) |
| データエクスポート | 初期スコープ外(将来、チーム管理画面からのCSVエクスポートを検討) |
| 対応環境 | iOS Safari / Android Chrome の最新版を主対象。PC管理画面はデスクトップ Chrome/Safari/Edge |

### 11.2 成績計算式の定義(§4.5の確定)

打席結果11種(単打・二塁打・三塁打・本塁打・四球・死球・犠打・犠飛・失策出塁・凡打・三振)から以下で算出する。

```
打席 PA  = 対象範囲の全打席結果の件数
打数 AB  = 単打 + 二塁打 + 三塁打 + 本塁打 + 失策出塁 + 凡打 + 三振
         ( = PA − 四球 − 死球 − 犠打 − 犠飛 )
安打 H   = 単打 + 二塁打 + 三塁打 + 本塁打
塁打 TB  = 単打×1 + 二塁打×2 + 三塁打×3 + 本塁打×4

打率  AVG = H / AB                                  ( AB = 0 のときは "-" 表示 )
出塁率 OBP = (H + 四球 + 死球) / (AB + 四球 + 死球 + 犠飛)   ( 失策出塁は出塁に含めない )
長打率 SLG = TB / AB                                 ( AB = 0 のときは "-" 表示 )
OPS       = OBP + SLG
打点  RBI = 打席入力時に手動付与した値の合計
```

基本カウントとして 打数・打席・安打・二塁打・三塁打・本塁打・四球・死球・三振・犠打・犠飛・打点 を表示する。

### 11.3 データモデルの確定(§5の詳細化)

Firestore のコレクション構成。ドキュメントIDは特記なき限り Firestore 自動採番。

| パス | フィールド |
|---|---|
| `teams/{teamId}` | `name`(string), `createdAt`(timestamp)。ドキュメントIDが §11.1 のチームID |
| `teams/{teamId}/players/{playerId}` | `name`(string), `number`(number \| null), `archived`(boolean, 既定 false) |
| `teams/{teamId}/games/{gameId}` | `date`(string, YYYY-MM-DD), `opponent`(string), `ground`(string), `season`(number, 西暦), `lineup`(playerId の配列, 打順順), `homeScores`(number[9]), `awayScores`(number[9]), `status`(`"in_progress"` \| `"finished"`), `createdAt`(timestamp) |
| `teams/{teamId}/games/{gameId}/atbats/{atbatId}` | `playerId`(string), `order`(number, 1〜), `inning`(number, 1〜), `result`(enum: `single` / `double` / `triple` / `homerun` / `walk` / `hitByPitch` / `sacBunt` / `sacFly` / `reachedOnError` / `out` / `strikeout`), `rbi`(number, 0〜4), `createdAt`(timestamp) |
| `admins/{uid}` | 存在すればアプリ管理者(フィールドは任意。`createdAt` 等) |

- 試合削除時は配下の `atbats` もクライアントから一括削除する。
- 成績集計はクライアント側で `atbats` を読み取り、§11.2 の式で算出する(集計結果の永続化はしない)。
- 「直前の記録」表示は、対象試合の `atbats` を `createdAt` 降順で取得して先頭を表示する。
