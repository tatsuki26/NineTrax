# 実装分担ドキュメント（2人並行）

`docs/仕様書.md`（特に §11）を前提とする。本ドキュメントは、2つの Claude Code セッションで並行実装するための共有契約（フォルダ構成・型・DBアクセス層のI/F）と、担当ごとのタスク定義をまとめたもの。

---

## 0. 実装できる段階か

**可能。** ブロッカーは §11 で解消済み。実装中に決めればよい細かい点は、以下のデフォルトで進める。

| 未定事項 | デフォルト |
|---|---|
| スタイリング | Tailwind CSS。UIライブラリは入れず自前コンポーネント |
| テスト | Vitest。必須は `lib/stats.ts` のユニットテストのみ |
| 現在の打者の特定 | 状態は持たず、`その試合の atbats 件数 mod lineup人数` で算出。直前レコード削除で1つ戻る |
| イニングの表裏 | `atbat.inning` は回数のみ（自チーム攻撃イニングとして記録）。表裏は保持しない |
| スタメン人数 | 9人固定にせず可変（草野球は人数不定）。`lineup` は任意長の配列 |
| 選手交代・代打 | 初期スコープ外。試合中の `lineup` 変更UIは作らない（作成時のみ設定） |
| Firebase環境 | dev/prod でプロジェクト分離。接続情報は `.env.local`（`NEXT_PUBLIC_FIREBASE_*`） |

### 1.2 型定義（`src/lib/types.ts` — 担当A が最初に確定して push）

```ts
export type AtBatResult =
  | 'single' | 'double' | 'triple' | 'homerun'
  | 'walk' | 'hitByPitch'
  | 'sacBunt' | 'sacFly'
  | 'reachedOnError' | 'out' | 'strikeout';

export const AT_BAT_RESULT_LABELS: Record<AtBatResult, string> = {
  single: '単打', double: '二塁打', triple: '三塁打', homerun: '本塁打',
  walk: '四球', hitByPitch: '死球',
  sacBunt: '犠打', sacFly: '犠飛',
  reachedOnError: '失策出塁', out: '凡打', strikeout: '三振',
};

export interface Team   { id: string; name: string; createdAt: number; }
export interface Player  { id: string; name: string; number: number | null; archived: boolean; }
export interface Game {
  id: string;
  date: string;          // 'YYYY-MM-DD'
  opponent: string;
  ground: string;
  season: number;        // 西暦
  lineup: string[];      // playerId、打順順、任意長
  homeScores: number[];  // 長さ9、未入力は 0
  awayScores: number[];
  status: 'in_progress' | 'finished';
  createdAt: number;
}
export interface AtBat {
  id: string;
  playerId: string;
  order: number;         // 1〜（打順）
  inning: number;        // 1〜
  result: AtBatResult;
  rbi: number;           // 0〜4
  createdAt: number;
}

// 集計結果（lib/stats.ts が返す）
export interface StatLine {
  pa: number; ab: number; h: number; tb: number;
  single: number; double: number; triple: number; homerun: number;
  walk: number; hitByPitch: number; strikeout: number;
  sacBunt: number; sacFly: number; reachedOnError: number; out: number;
  rbi: number;
  avg: number | null;   // AB=0 は null（UIで "-" 表示）
  obp: number | null;
  slg: number | null;
  ops: number | null;
}
```

## 2. 担当A：基盤・データ層・管理画面

### スコープ
1. **プロジェクト初期化** — Next.js 15 (App Router, TS)、Tailwind、Firebase SDK、Vitest、ESLint/Prettier。`.env.local.example` を用意
2. **`src/lib/firebase.ts`** — クライアント初期化、Firestore オフライン永続化(IndexedDB)有効化
3. **`src/lib/types.ts`** — §1.2 のとおり。**最優先で確定して push**（担当B のブロッカー）
4. **`src/lib/ids.ts`** — 12文字 base32(a-z,2-7) の暗号学的乱数
5. **`src/lib/db/*` + `hooks.ts`** — §1.3 の I/F を実装
6. **`src/lib/stats.ts` + テスト** — §11.2。境界（AB=0で null、失策出塁は OBP 分子に入れない、犠打は OBP 分母に入れない）をテストで固定
7. **`firestore.rules` / `firestore.indexes.json`** — teamId 配下は誰でも読み書き可、`admins/{uid}` 存在で管理判定、App Check。`games` の `season` フィルタ用インデックス
8. **`scripts/seed.ts`** — 初期チーム1件＋管理者(`admins/{uid}`) を作成
9. **アプリ管理画面** — `/admin/login`（Firebase Auth email/password）、`/admin/dashboard`（全チーム一覧、チーム作成・削除、アクティブチーム数・試合数の集計表示）。`admins/{uid}` 判定でガード
10. **チーム管理画面** — `/team/[teamId]/admin`（PC想定）：選手一括管理、試合一覧の編集・削除、成績確認、チームID再発行（確認ダイアログ）、チーム名編集
11. **`src/app/team/[teamId]/layout.tsx`** — teamId でチーム取得、無ければ 404、共通ナビ
12. **`src/components/`** — Button / Modal / Field / Table などの雛形

### 完了条件
- 担当B が `import { usePlayers } from '@/lib/db/hooks'` 等でビルドが通る
- `pnpm test` で stats のテストが緑
- seed 実行 → 管理ログイン → チーム作成 → 発行URL が開ける

## 3. 担当B：チーム向けスマホ機能

前提：担当A の `src/lib/types.ts` と `src/lib/db/*` の I/F（§1.2〜1.4）。実体が未 push の間は I/F に対してモック（`db` 関数を Promise で握るスタブ）を置いて進めてよい。

### スコープ
1. **`/team/[teamId]` チームホーム** — 選手一覧・試合一覧（`usePlayers` / `listGames`）、試合作成への導線
2. **`/team/[teamId]/players` 選手管理** — 登録・編集・論理削除（名前・背番号）。スマホUI
3. **`/team/[teamId]/games/new` 試合作成・スタメン設定** — 日付・対戦相手・球場・season 入力、選手を選んで打順に並べる（任意人数）、`createGame`
4. **`/team/[teamId]/game/[gameId]` 打席入力** — 中核。以下を1画面に：
   - 現在の打者を表示（`atbats.length mod lineup.length` で算出。`useAtBats` でリアルタイム）
   - 結果11種のタップボタン（`AT_BAT_RESULT_LABELS`）＋ 打点 0〜4 ステッパー → `addAtBat`、打順は自動で次へ
   - 手動「イニング送り」ボタン（現在イニングの number を +1）
   - 打席ログ一覧（新しい順）、各行に編集・削除（`updateAtBat` / `deleteAtBat`）。「直前の記録」を最上部に強調表示
   - 複数端末で即時反映されること（`useAtBats` の onSnapshot）
5. **スコアボード** — 同画面 or タブ。1〜9回＋合計の表、自/相手のセルをタップして得点手入力 → `updateGame({ homeScores/awayScores })`。合計は表示のみ
6. **`/team/[teamId]/stats` 個人成績** — `computeByPlayer` を使い、通算（season で絞り込み）と試合ごとの両方。AB=0 は "-" 表示。列は §11.2 の基本カウント＋ AVG/OBP/SLG/OPS/打点

### 完了条件
- 実機（iOS Safari）で打席入力→別端末に反映を確認
- 誤入力を直前レコード編集・削除で訂正できる
- 成績画面の数値が §11.2 の手計算と一致
